# NOVA Capability Uplift Test — Evaluation Harness

**Question:** does attaching the NOVA Cognitive Adapter to a small Meta
language model let it correctly answer previously unseen questions
that the same model cannot answer alone?

This harness is the experiment. It is operational now; the live
model comparison is measured (see EVAL_RESULTS.md §9). No new
features are being built until this experiment runs.

## Layout

- `eval/gen_eval.py` — set generator (fixed seeds; asserts zero
  overlap with the development probes and between eval/holdout).
- `eval/gen_fresh.py` — fresh independent set generator (seed
  20261029; same categories/coverage as frozen; asserts zero overlap
  with frozen, holdout, and money probes).
- `eval/harness.py` — arms, recording, classification, comparison
  guard, ablation runner.
- `eval/normalize.py` — answer normalization (number / yes-no /
  keyword text; abstention is a first-class answer).
- `eval/metrics.py` — Wilson 95% CI, paired bootstrap 95% CI for net
  improvement, regression rate, latency, cost.
- `eval/mock_model.py` — deterministic mock model (mechanics only).
- `eval/live_model.py` — live Muse Spark 1.3 adapter (both harness
  interfaces; enforced `max_tokens=2048` — 128 provably truncates
  this reasoning model to an empty answer; per-thread usage
  accounting; fail-fast on 429/401/403).
- `eval/analyze.py` — failure clustering + per-module recommendations.
- `eval/run_eval.py` — CLI.
- `eval/fixtures.py` — authored dictionary/encyclopedia fixture
  entries (written for this harness, not scraped; the production
  store still ships empty).
- `eval/runs/` — append-only run logs (JSONL, one record per
  question) + per-run summary JSON. Never overwritten.
- `data/eval_uplift.jsonl` — frozen eval set (250).
- `data/eval_uplift_holdout.jsonl` — frozen holdout (100).
- `data/eval_uplift_fresh.jsonl` — fresh independent set (250).
- `data/eval_manifest.json` — seeds + SHA-256 hashes of both sets.
- `data/eval_fresh_manifest.json` — seed, generator, counts,
  SHA-256, and disjointness proof for the fresh set.
- `tests/test_eval_harness.py` — 34 harness-mechanics tests.

## The frozen sets

Generated with fixed seeds (eval 20261027, holdout 20261028), fresh
name/amount pools, and an independent expected-value simulation.
Zero text overlap with `data/money_probes.jsonl` (verified by the
generator and by test). Dictionary/encyclopedia holdout items ask
about *different terms* than the eval set (separate fixture pools).

Eval set (250): deterministic 110 (money 60, calculator 20,
symbolic 30) · unfamiliar NL 100 (synonym 20, antonym 15, negation
20, multi-step 20, ambiguous 10, hard negative 15) · knowledge 40
(dictionary 20, encyclopedia 10, knowledge combos 10). Holdout (100)
uses the same process, proportionally.

Every item: id, group, category, module, adversarial tags, question
text, answer kind (number / yes-no / text), ground truth, and — for
items whose module can only be reached through a structured request
(calculator, dictionary, encyclopedia, rule syllogisms) — a
`nova_request` plus `input_mode: structured_oracle`. The NOVA arm
tries the raw-text path first and only uses the oracle request when
the text path yields no answer; the text-path failure is recorded in
the trace, so oracle use is never hidden.

## The fresh independent set

Generated by `eval/gen_fresh.py` (seed 20261029) after the audit of
the frozen live benchmark, to test the system on questions it was
never built against. Same categories and counts as the frozen set
(deterministic 110 / unfamiliar NL 100 / knowledge 40). Verified
disjoint from the frozen 250, the holdout 100, and the money probes
(0 text overlaps, recorded in `data/eval_fresh_manifest.json`).

Two deliberate differences from the frozen set: dictionary /
encyclopedia items reuse the frozen set's terms with NEW phrasings
(the fixture term pools are exhausted — genuinely new terms await
the Phase 2 licensed store), and the 4 fixed syllogisms are replaced
with 4 fresh ones (Maya/doctor, trout/fish, apple/fruit, Omar/pilot).
The fresh set also exposed a case the frozen set never exercised:
an unknown-symbolic item where the asked amount MATCHES the story
amount ("Omar gave Felix $22. Did Omar pay Nina $22?") — the
pipeline answers "no" (closed-world overreach) where the ground
truth is "unknown" (see EVAL_RESULTS.md §10).

## The three arms

- **`alone`** — the model answers the raw question from a fixed
  prompt (template v1, recorded in every run). No NOVA anywhere.
- **`retrieval`** — the model answers from template v1 plus a
  "Relevant knowledge from the concept store:" block when the store
  has an entry for the question (dictionary/encyclopedia lookup
  ONLY — no NOVA reasoning, no calculator). Retrieval mirrors the
  NOVA arm's routing: each sentence is offered to `route_sentence`
  and only retrieved definition frames are collected. A naive
  whole-text lookup is wrong here: it spuriously returns "receipt"
  on 41/60 money items (its meaning shares "money" and "received"
  with the story). When no entry is found the prompt is
  byte-identical to the alone prompt, so the arm is a clean control.
- **`nova`** — the same model, same checkpoint, same decoding
  settings, with NOVA attached: the deterministic pipeline answers
  from shared ConceptFrames; the model is an optional advisor whose
  output is recorded separately and never substituted for the proven
  answer.

The key gap is **nova − retrieval**: the part of the improvement
that is reasoning, not lookup. `summarize_three_way` reports all
three pairwise gaps with paired-bootstrap 95% CIs.

**Comparison guard:** `run_comparison` refuses loudly unless both
runs share the identical model config (model_id, checkpoint,
temperature, max_tokens) and neither ran with model=None. A
deterministic-only NOVA run is a standalone measurement, never one
side of a comparison.

## How to run

```sh
# Regenerate / verify the frozen sets (does not run anything)
python3 -m eval.gen_eval            # writes both sets + manifest
python3 -m eval.gen_eval --check    # verify counts/coverage/overlap

# Deterministic NOVA path (real result, available today)
python3 -m eval.run_eval nova --set eval

# Module ablation (baseline + one module off at a time)
python3 -m eval.run_eval ablations --set eval

# Mock-model mechanics validation (labeled MOCK everywhere)
python3 -m eval.run_eval mock --set eval

# LIVE comparison (Muse Spark 1.3, both arms, same config)
python3 -m eval.run_eval live --set eval --limit 10   # smoke test
python3 -m eval.run_eval live --set eval --workers 4  # full run

# LIVE three-arm comparison on the fresh set (alone / retrieval / nova)
python3 -m eval.run_eval live3 --set fresh --limit 10 --workers 4
python3 -m eval.run_eval live3 --set fresh --workers 4  # full run

# Compare two existing run files (refuses mismatched configs)
python3 -m eval.run_eval compare --alone eval/runs/A.jsonl \
    --nova eval/runs/B.jsonl

# Failure analysis for a run file
python3 -m eval.run_eval analyze eval/runs/A.jsonl

# Harness unit tests
python3 -m tests.test_eval_harness
python3 tests/run_all.py   # full suite, includes the harness tests
```

## The holdout

`--set holdout` is **refused** unless `--final` is passed. A final
run is logged to `eval/FINAL_EVALUATION_LOG.md` and every record is
marked `final_evaluation: true`. Do not run the holdout during
development — it is the only clean final read.

## What is recorded per question

Question, raw response (full envelope for NOVA, raw text for the
model), normalized answer, ground truth, latency (ms), token usage
(null/unknown when no model is called — never fabricated), cost
($0.00 until live pricing exists), module trace (which NOVA modules
ran, input mode, status, verdict, completeness, frames, missing
slots), and the classification (wrong→correct / correct→wrong /
correct→correct / wrong→wrong, filled in by comparison).

## Metrics

Accuracy per arm (Wilson 95% CI) · net improvement with a paired
bootstrap 95% CI (2,000 resamples, fixed seed) · regression rate
(share of alone-correct items NOVA loses) · latency (mean/median/p95)
· cost · per-group and per-category breakdowns.

## The mock model

`eval/mock_model.py` is a deterministic set of crude heuristics
(canonical-"gave" money math, lexical-overlap yes/no, seeded recall
of the fixture dictionary). It exists only to prove the harness
mechanics work. Its accuracy says nothing about any real model. Every
mock run is labeled `mock: true` in the run file, the run id, and the
report.

## Ablation

`ablations` toggles one module at a time through the pipeline's
`ablations` parameter (added for this harness; default behavior
unchanged): `heuristic` (tier-2 5W1H extraction off),
`calculator`, `dictionary`, `reasoner` (propositional yes/no off),
`memory`. The accuracy delta vs baseline attributes the improvement
to the module.
